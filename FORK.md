# Fork notes

Trimmed fork of [caelestia-dots/shell](https://github.com/caelestia-dots/shell) for Fedora Asahi (Apple Silicon)
on Hyprland, themed Catppuccin Mocha. Runs without the `caelestia` CLI. Remote `upstream` points at the
original repo; merge from it to update.

## Changes from upstream

- **Removed** (code and build deps): launcher calculator (`libqalculate`), audio visualiser bars and the
  media tab's visualiser ring (`libcava`), beat tracking for the bongo cat GIF (`aubio`), and the PipeWire
  audio capture they shared (`libpipewire`). Config: `background.visualiser`, `services.visualiserBars`,
  `general.mediaGifSpeedAdjustment`.
- **Fixed theme**: `services/Colours.qml` reads `assets/scheme.json` (Catppuccin Mocha, lavender accent),
  generated by `scripts/catppuccin-scheme.py`. Removed scheme/variant switching from the launcher, the
  light/dark toggle and launcher actions, and `services.smartScheme`.
- **Wallpapers**: `services/Wallpapers.qml` stores the current wallpaper in
  `~/.local/state/caelestia/wallpaper/path.txt` itself, with no scheme generation. Added IPC
  `wallpaper random`; the launcher's Random and Settings actions use `qs -c caelestia ipc call`.
- **Recording**: `assets/record.sh` uses `wf-recorder` instead of gpu-screen-recorder. wf-recorder can't
  pause, so the pause button is removed.
- **Removed widgets** for dependencies that aren't installed (widgets only, their sections stay):
  - power-profiles-daemon: profile switcher and "performance degraded" warning in the battery pop-out
  - caelestia CLI: CLI version row (About), "Smart colour scheme" toggle (Services), "Dark theme" toggle
    and "Colours" button (Wallpaper & style), "Schemes"/"Variants" fuzzy-search toggles (Launcher)
- **Brightness**: monitors without DDC (all external monitors on Asahi) are not controllable
  (`Brightness.Monitor.controllable`): no OSD brightness slider, no bar-scroll/IPC changes. Upstream falls
  back to brightnessctl for them, which changes the laptop panel instead.
- **Temperatures**: a reading of 0 (the services' value when there's no sensor) shows "N/A" on the performance
  cards and lock screen. Asahi exposes no CPU/GPU die temperature, and the CPU service only knows Intel/AMD labels.

## Build

Only the C++ parts are built; the repo itself is the Quickshell config (`qs -c caelestia`).

```sh
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DENABLE_MODULES="extras;plugin" \
    -DCMAKE_INSTALL_PREFIX="$HOME/.local" -DCMAKE_INSTALL_LIBDIR=lib
cmake --build build
cmake --install build
```

Needs [m3shapes](https://github.com/soramanew/m3shapes) in the same prefix, and at runtime
`QML_IMPORT_PATH=~/.local/lib/qt6/qml` and `CAELESTIA_LIB_DIR=~/.local/lib/caelestia`.
